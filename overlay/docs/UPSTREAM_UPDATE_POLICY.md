# KSM 원본 업데이트 대응·버전별 유지 방침

적용일: 2026-11-17. 이 문서는 향후 원본 KSM 업데이트를 모드에 반영할 때 따르는 프로젝트 운영 기준입니다.

## 기본 원칙

**원본 KSM의 새 버전은 별도 브랜치에서 이식하고, 기존 원본 버전용 모드는 유지합니다.** 새 원본이 나왔다고 이전 소스·브랜치·설치기·릴리즈를 덮어쓰거나 삭제하지 않습니다.

- 원본 버전과 모드 버전은 구분합니다. 같은 모드 버전이라도 지원 원본 버전이 다르면 별도 산출물입니다.
- 새 원본의 수정·개선과 기존 모드 기능을 함께 검토합니다. EXE 버전 문자열과 설치기 허용 목록만 바꾸는 이식은 하지 않습니다.
- 이전 버전의 보존은 계속적인 기능 추가나 무기한 지원을 뜻하지 않습니다. 지원 범위·미검증 항목은 버전별로 기록합니다.
- 기본 브랜치 변경, 이전 브랜치 삭제, 공개 배포·원격 푸시는 각각 해당 작업의 승인 범위에 따라 처리합니다. 문서에 절차가 있다는 이유만으로 수행하지 않습니다.

## 브랜치와 작업 폴더

1. 대응할 원본의 정식 태그와 전체 커밋 SHA를 고정합니다. 기존 모드 기준 커밋·설정·빌드·검사 결과도 확보합니다.
2. 두 소스 저장소에 `feature/ksm-X.Y.Z` 형태의 별도 이식 브랜치를 준비합니다. 예: `feature/ksm-2.2.0`.
3. 기존 개발 폴더와 play-test를 그대로 두고, 별도 worktree/작업 폴더와 격리 실행 폴더를 사용합니다.
4. 전체 소스 포크는 원본 이력을 유지하며 병합합니다. 독립 mod 저장소는 해당 원본 커밋을 기준으로 patch＋overlay와 의존성 매니페스트를 재생성합니다.
5. 기존 버전의 브랜치는 새 원본으로 전환하지 않습니다. 추후 기본 브랜치를 바꾸기로 결정한다면, 이전 버전의 마지막 상태를 독립 유지 브랜치와 고정 태그로 먼저 보존합니다.
6. 원격 푸시가 승인된 경우에도 기존 이력을 강제 덮어쓰지 않습니다. 새 버전 작업을 이유로 이전 브랜치·태그·릴리즈를 정리하지 않습니다.

현재 구분의 예시는 다음과 같습니다. 새 브랜치가 로컬에만 준비된 상태와 원격에 게시된 상태는 구분해서 보고합니다.

| 대상 | 기존 2.1.0용 | 별도 2.2.0용 |
|---|---|---|
| 전체 소스 포크 | `enhanced-vertical` | `feature/ksm-2.2.0` |
| 독립 patch＋overlay | `main` | `feature/ksm-2.2.0` |
| 개발 폴더 | `ksm-enhanced-vertical/` | `ksm-enhanced-vertical-220/` |

## 원본 개선과 모드 기능의 연계 절차

- 원본 변경 커밋·파일·의존성·UI·언어·리소스를 이전 기준과 비교합니다. 자동 병합된 영역도 의미가 맞는지 확인합니다.
- 선곡/캐시, 경로, 입력/판정, 게이지/기록, 렌더/레이저, 오디오, 옵션/UI, 스킨과 설치기를 영역별로 검토합니다.
- 원본의 의도된 버그 수정은 유지하고, 그 위에 EX/P-CRITICAL·APS·세로 화면·프리뷰·스킨·ASIO 등 모드 기능을 연결합니다. 이전 동작과의 차이가 원본 수정 때문인지 이식 오류 때문인지 구분합니다.
- 버전별 `docs/MIGRATION_X.Y.Z.md`에 원본 기준, 모드 기준, 연계 변경, 검사 결과, 제한을 남깁니다. 주요 원본 수정과 검증의 대응표도 작성합니다.
- 외부 라이브러리는 해당 원본의 고정 버전에 모드 패치를 재적용합니다. 공개되지 않은 로컬 의존성 커밋만 가리켜 빌드가 재현되지 않는 상태를 만들지 않습니다.

## 설치기·배포물 분리

- EXE·ZIP 이름은 모드 버전만 넣어 간결하게 유지합니다. 예: `KsmEnhancedVertical_<mod-version>_Setup.exe`. 지원 원본 버전은 설치기 UI·빌드정보·README와 업데이트 메타데이터에 명시하고, 배포 폴더를 원본 버전별로 분리합니다.
- 버전별 지원 원본과 설치 계약(runtime contract)을 구분합니다. 다른 원본 버전의 설치 기록은 파일 변경·복구 전에 차단하고 올바른 설치기를 안내합니다.
- 같은 원본 버전 안의 지원 모드 업데이트와, 원본 버전 자체를 바꾸는 마이그레이션은 별개의 작업입니다.
- 원본 버전 간 자동 업데이트·설치 기록 변환은 기본적으로 제공하지 않습니다. 별도 설계와 검증이 승인된 경우에만 지원합니다.
- QA는 별도 원본 게임 폴더에서 수행합니다. 기존 모드를 제거하고 원본을 업데이트하는 경로는 필요한 경우 따로 검증·안내합니다.
- 이미지·UI·언어·설정·악곡·스킨 등 사용자마다 달라질 수 있는 파일의 원본 해시 일치를 설치 조건으로 요구하지 않습니다. 원본 EXE/DLL 호환성, 패키지 무결성, 백업 검증, 수정 파일 식별은 별도로 검사합니다.
- 점수·EX·코스 기록, 설정·오프셋·키 배치, 악곡·사용자 스킨과 수정 이미지를 보존합니다. 지원 원본이 바뀌었다는 이유로 사용자 데이터를 초기화하거나 일괄 다시 쓰지 않습니다.
- 최초 원본 백업·업데이트 실패 복구·제거 정책도 버전별로 검증합니다. 기존 설치 ZIP과 릴리즈는 그대로 남깁니다.

## 검증과 배포 판단

1. 새 원본 테스트를 유지하고, 모드의 판정·EX·APS·설정·스킨·기록 호환 검사를 실행합니다.
2. 가로·세로 일반 플레이, 선곡, 결과, 옵션, 프리뷰, 판정 설정과 지원 언어의 화면·조작을 확인합니다.
3. 설치 → 실행 → 제거 → 재설치, 지원하는 동일 원본 내 업데이트, 다른 원본 차단, 실패/중단 복구와 사용자 파일 보존을 검사합니다.
4. patch＋overlay를 새 폴더에 복원해 전체 소스와 수정 의존성이 실제 빌드한 코드와 같은지 확인합니다.
5. 실제 장치의 오디오 싱크·하드웨어 성능·OBS 부하는 모의/무음/소프트웨어 렌더링 검사와 구분합니다. 수행하지 않은 검사는 통과로 기록하지 않습니다.
6. 검증 중인 버전은 QA로 표시합니다. 공개 릴리즈 여부는 결과와 남은 제한을 확인한 뒤 별도로 결정합니다. 단순 빌드 성공을 전체 동작 보장으로 표현하지 않습니다.

테스트 실행은 사용자의 작업 환경을 방해하지 않아야 합니다. 별도 요청이 있기 전까지 음성 출력 없는 검증을 우선하고 실제 오디오 장치를 자동으로 열지 않습니다. 화면 검사는 전환하지 않는 격리 데스크톱 또는 왼쪽 보조 모니터를 사용하며 포커스·최상위 표시·전역 입력을 가져오지 않습니다.

## 이전 버전 유지보수

- 새 버전 안정화 후에도 이전 버전의 소스·태그·배포물·검증 자료는 보존합니다.
- 공통 버그 수정은 각 원본 버전에서 필요한지 검토한 뒤 따로 반영·검증합니다. 새 원본의 코드를 이전 버전에 무조건 역이식하지 않습니다.
- 이전 버전 수정은 해당 버전 브랜치에서 처리합니다. 새 버전 이력을 합쳐 지원 원본을 암묵적으로 바꾸지 않습니다.
- 기능 추가나 지원 종료를 결정하면 해당 버전 문서에 명시합니다. 이 방침만으로 기존 버전의 지원 종료나 브랜치 삭제를 승인한 것으로 보지 않습니다.
